# Tales, Part 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A designer can write a Tale (a campaign box): its story, its scenarios in order, its difficulty modes, its log entries and its three kinds of card — and edit, print and round-trip it through `design/`.

**Architecture:** A Tale is a new owner beside scenarios, modules, characters and domains. Its entity-side cards are ordinary modules with `modules.tale_id` set, hidden from ordinary play; its reward cards are ordinary player cards with `player_cards.tale_id` set; its own cards are a new `tale_cards` table with a new card face. The story and the log sheet print as one text page in the rulebook's style, not on the card grid.

**Tech Stack:** Laravel 11, Vue 3, Inertia 3, Tailwind, SQLite, PHPUnit.

**Spec:** `docs/superpowers/specs/2026-11-16-tale-design.md` (Part 1 only — Part 2, the table keeping the log, gets its own plan).

## Global Constraints

- PHP floor is 8.4. No dependency changes.
- **Never run the full suite** — it commits to the real repo (see memory). Run `php artisan test --filter=<TestClass>`.
- Inertia has `ensure_pages_exist: true`: after adding a page under `resources/js/Pages`, run `npm run build` before its feature test.
- Work on a branch (`git switch -c tale`). `main` carries unrelated uncommitted work: `git add` only the files a task lists, never `-A`.
- Every new row defaults to `is_placeholder = true`. Nothing is written on the designer's behalf: a Tale with no modes has no modes.
- The UI word is **Tale** everywhere. Do not touch *storyline* or *story beat*.
- Two-halves rule: every change to a card face lands in both `resources/js/Components/CardPreview.vue` and `resources/views/print/partials/card.blade.php`.
- Design files: keys camelCase, two-space JSON via the existing `writeJson()`; a key a Tale adds to an existing file is written **only when set**, so existing files export byte for byte.
- Report, don't correct: an import that names a missing scenario or module skips it and says so (`$this->warn`), it never invents one.

## Review Focus

1. **A Tale's module leaking into ordinary play** — any of the seven `Module::` lists (scenario form ×2, deck assembly, play setup, `compatibleModules`, nav, modules index, pocket) still showing it. Test in Task 2 covers every list.
2. **Deleting a Tale reaching outside it** — a scenario a step names, or a shared module a step uses, must survive. Test in Task 1.
3. **Upgrade links crossing owners** — a reward's `siblings()` must not sweep in every card with null character and domain. Test in Task 3.
4. **Export of a folder with no Tales** — must grow no `data/tales/` directory and change no module file. Test in Task 9.
5. **The log sheet with no steps or no entries** — must render (an empty grid with a note), not throw. Test in Task 8.
